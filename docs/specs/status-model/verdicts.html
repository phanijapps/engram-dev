Decision D-8 agent recommendation: accept

Decision D-9 agent recommendation: accept

The spec section anatomy is: why, stories (title, as/want/so, priority, independent_test, acceptance as given/when/then), edge_cases, requirements (plain MUST, serves a story, no scenarios), success_criteria, constraints, questions, assumptions, out_of_scope. Story done = its ACs met by done tasks.

Because: Three primary sources agree on the load-bearing parts: ACs live on the story (Atlassian 3 C's Confirmation; Spec Kit Acceptance Scenarios verbatim in templates/spec-template.md), priority and independent testability live on the story with the P1-alone-is-MVP rule (Spec Kit), requirements are plain MUST statements (Spec Kit FR-NNN, Kiro EARS), and success criteria and assumptions are spec-level sections we lack.
