# Input from new-project

Read this guide when a new-project conversation or artifact supplies roadmap input.
It is a handoff contract, not a claim that new-project emits a fixed schema.
Accept equivalent context from a conversation, brief, discovery record, or existing product.
No invocation of new-project is required for standalone use.

Reuse available evidence for:

- Product purpose, target audience, unmet need, and initial value proposition.
- Objectives and key results, or other desired outcomes and success signals.
- Smallest useful product, explicit exclusions, and proposed later capabilities.
- User journeys, domain rules, architecture constraints, and shared interfaces.
- Available people, skills, budget, capacity, horizon, and supplied deadlines.
- Upstream providers, downstream consumers, external commitments, and lead times.
- Actual owner decisions, proposals, assumptions, unresolved questions, and source references.

Do not require all these fields before producing a useful draft.
Use only the subset relevant to prioritization. Ask about material gaps once.
Carry unanswered questions forward with their impact; do not repeat resolved interviews.
Conflicting inputs remain conflicts until an authoritative source resolves them.

Turn MVP capabilities into candidate outcome initiatives rather than one task per feature.
Place validation before expensive commitments where demand or feasibility is untested.
Keep explicit exclusions intact. Do not add a default platform, enterprise features,
or infrastructure program without evidence that the product needs it.

Technical preferences are constraints or proposals according to their recorded status.
Product agreement does not imply accepted design decisions or permission to implement.
If scaffolding already exists, treat it as current evidence, not proof of product value.

Return the roadmap, the next proposed initiative, unresolved decisions, and the inputs
needed by analyze or the project's equivalent delivery process.
If roadmap is unavailable, new-project can provide this context directly as a handoff.
Neither skill should silently invoke the other in a recursive loop.
