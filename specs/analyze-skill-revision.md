# Analyze skill revision

Date: 2026-10-11 (America/New_York). Command traces retain their actual UTC times.

This revision fixes the authoritative `analyze` skill and supporting templates. It preserves the existing six modes and separates ordinary repository questions from executable initiatives. It adds current harness commands, supported locked registration, dirty-source evidence, bounded dependency analysis, explicit owner gates and immutable re-analysis. The original evaluation remains in `analyze-skill-evaluation.md`; this report records the subsequent fixes and experiments.

## Changes

- Ground relevant source and knowledge before residual questions. Record dirty and untracked evidence with hashes; a fresh HEAD stamp cannot establish those bytes. Do not reset the knowledge baseline during analysis.
- Inspect relevant upstream assumptions and downstream effects across components, APIs, events, entities, migrations, authorization, compatibility and failure paths. Match depth to the proposed change.
- Classify source gaps, experiments, human spec questions and design choices separately. Empty spec questions skip only that ceremony; proposed decisions and implementation permission keep their distinct gates.
- Register actual candidate requirements and artifact hashes with the current core loader, shared lock and held revision. Canonical requirements use supported `FR-*` fields. An initialized shell or passing alignment alone is insufficient.
- Preserve earlier artifacts, closed packs and approved digest bindings. Add successors instead of rewriting their bytes or granting fictional authority.
- Treat hook context as orientation. Verify canonical discovery and actual admission; an explicit independent question can proceed without selecting unrelated open work.
- Capture deciding probe evidence before concluding. A failed assertion does not establish its proposition. Keep reusable check procedures distinct from each workspace's actual findings.
- Declare the spike method and timebox before executing any experiment, including a supplied diagnostic. Record actual start and elapsed time.

The new `resources/operations.md` covers current commands, normalized/canonical field mapping, locked authoring, audit and durability limits, reference verification and known context refusal. All six templates include bounded scope, classified uncertainty and concrete planning handoffs. Evaluation recipes and the rubric distinguish content, ordered process and filesystem deltas.

The related wiki concept `wiki/domain/pattern-anti-waterfall-loop.md` now cites the current shared artifact contract and retains explicit owner gates.
