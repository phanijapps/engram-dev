## Findings

### DEFECT

**1. Canonical JSON can escape the pack through a symlink.** [store.ts:113](../../treadle/packages/core/src/feedback/store.ts) and the locked reload at line 622 guard the directory and feedback files, then use the unguarded core loader for canonical JSON. Failing scenario: `specs/own/own.json` points to another project's active pack outside the workspace; opening feedback succeeds and creates a local ledger with `pack_id: foreign-project-pack`. The existing library's `loadContainedPack` explicitly rejects this pattern. **Fix:** validate the discovered canonical JSON's containment and symlink boundary on every read and locked reload, and reuse that guarded boundary in snapshot and browser consumers. Evidence: [implementation-red-canonical-probe.json](checks/implementation-red-canonical-probe.json). The in-progress T-3 route's unguarded load needs the same boundary.

**2. Missing Git objects initiate an implicit remote fetch.** [feedback-snapshot.ts:82](../../treadle/packages/cli/src/harness/feedback-snapshot.ts), through the `cat-file` calls at lines 117–121, permits promisor lazy fetching. Failing scenario: a partial repository has a missing selected blob; the builder invokes the configured upload-pack helper before eventually reporting unavailable. The controlled probe executed a local marker helper and used no network; a configured network remote uses the same fetch path, contrary to the approved offline constraint. **Fix:** prohibit Git remote transports/lazy fetch for every snapshot child process and refuse absent local objects before external transport can run. Evidence: [implementation-red-git-probes.json](checks/implementation-red-git-probes.json).

**3. Ambient Git routing can substitute a foreign repository.** [feedback-snapshot.ts:84](../../treadle/packages/cli/src/harness/feedback-snapshot.ts) inherits routing variables. Failing scenario: `GIT_DIR` selects another repository while `GIT_WORK_TREE` names the enrolled workspace; the top-level check passes, `HEAD` resolves to the foreign commit, and the before side contains foreign repository bytes. **Fix:** sanitize Git routing/index environment variables and bind every object/index operation to the selected repository; add an ambient-environment regression. Evidence: [implementation-red-git-probes.json](checks/implementation-red-git-probes.json).

**4. Retrying Open can skip already submitted feedback.** [feedback.ts:224](../../treadle/packages/cli/src/commands/feedback.ts) constructs the Open response from the session's current cursor. Failing scenario: the first Open acknowledgement is lost, the owner submits batch 1, then the agent retries the original operation; the response reports pending with cursor 1, and waiting after that cursor returns no batch. Reading after the original session cursor 0 returns the missed request. **Fix:** return the original Open cursor from its committed receipt, preserving it across retry rather than advancing it to current submitted feedback. Evidence: [implementation-red-probes.json](checks/implementation-red-probes.json).

**5. UTF-8 BOM stripping violates exact snapshot bytes and breaks replay.** [feedback-snapshot.ts:66](../../treadle/packages/cli/src/harness/feedback-snapshot.ts) and [store.ts:452](../../treadle/packages/core/src/feedback/store.ts) use the default TextDecoder behavior. Failing scenario: selected bytes `efbbbf6f6e650a` become stored bytes `6f6e650a`. A direct core snapshot containing the BOM is returned without it, so CLI replay reconstructs another payload and conflicts with the original operation ID. **Fix:** preserve BOM bytes during exact UTF-8 decoding, including snapshot reads/replay, and test document and Git sides. Evidence: [implementation-red-probes.json](checks/implementation-red-probes.json).

**6. Published-operation retry omits the new directory's parent flush.** [store.ts:637](../../treadle/packages/core/src/feedback/store.ts) flushes the ledger and its parent but omits the pack-directory flush performed by ordinary success at line 777. Failing scenario: first Open publishes its ledger but loses acknowledgement before final durability flushing; retry acknowledges success after flushing `feedback/state.json` and `feedback/`, while the newly created `feedback/` entry in the pack directory remains unflushed. The probe observed this exact fsync sequence; it does not claim to simulate physical power loss. **Fix:** complete the same required publication durability chain on committed-operation replay, including the parent entry for a newly created feedback directory. Evidence: [implementation-red-probes.json](checks/implementation-red-probes.json).

### DEFECT 7 — replay re-resolves a mutable Git baseline

[feedback.ts:65](../../treadle/packages/cli/src/commands/feedback.ts) rebuilds the committed operation's selection using today's `resolveFeedbackCommit` at lines 69–70. Failing scenario: Open with `mode: diff`, `base: HEAD`, selected `source.ts`, a stable UUID and revision 0 succeeds; after an unrelated commit moves HEAD, the identical request/UUID/revision returns `conflict: Operation ID was reused with another payload`, instead of its committed receipt. An accepted document request carrying `base: HEAD` also succeeds initially because document snapshot construction ignores that field, then an immediate identical retry conflicts because replay adds it. Both cases contradict DES-1's committed-operation replay rule and native retry recovery. **Fix:** bind the original request identity to the committed resolved selection and replay that immutable selection without resolving mutable Git refs; handle irrelevant document flags consistently on first execution and replay. Evidence: [implementation-red-reference-retry.json](checks/implementation-red-reference-retry.json) and [implementation-red-reference-retry.log](checks/implementation-red-reference-retry.log). The fixture is local and synthetic; it commits only inside temporary repositories.

### Resolved BLOCKER — server/client output collision

During review, the T-3 server module `src/feedback.ts` and approved T-4 browser asset `src/feedback.js` mapped to the same `dist/src/feedback.js`. `scripts/copy-assets.mjs:7` overwrites the compiler output, so `project-server.ts` importing the route from `./feedback.js` would fail in the packaged runtime. The implementer moved the route into the already approved `project-server.ts` and made `feedback.ts` a source-level re-export. The server has no runtime dependency on the browser asset. The independent native Node smoke imports `web/dist/src/index.js`, starts the local project server, receives feedback state HTTP 200, and receives the library and actual browser asset HTTP 200. Evidence: [implementation-red-packaged-route.json](checks/implementation-red-packaged-route.json) and [implementation-red-packaged-route.log](checks/implementation-red-packaged-route.log). The reviewer did not rebuild or change generated/source files; it used the implementer's existing build output.
