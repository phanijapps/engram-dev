# Background harness brief

Make the existing knowledge-first SDD workflow available through one background local web app and reliable agent context. PO, Dev Lead, Dev and QA take turns in the same session on one machine. This proposal adds the missing connection layer; the existing JSON workflow and approvals remain authoritative.

The user requested `treadle start serve` and `treadle stop serve`, project installation that ensures the service then registers the workspace, wiki/spec access, and integrations for Codex, Claude Code and pi on Linux, macOS and Windows. The user clarified that an explicit stop is followed by restart on the next session event, and that the existing SDD capability should be reused.

These are requirements from this conversation, not design acceptance or permission to implement. This pack is proposed, all tasks are todo, and there are no owner acts or task results. Native host trust/activation is a distinct readiness condition and remains under human control.

Outcome: install runtime → install/activate host integration → enroll workspace → open project/wiki/spec → create or continue through existing gates → evidence → independent review → human Finish. New-spec authoring initially remains agent/CLI driven. Knowledge upkeep is explicit existing practice, not an automatic closure hook.
