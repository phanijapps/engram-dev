# Compact design supplement

D-1, D-2, and DES-1 through DES-3 retain the proposal in `design.md`.
The added subsystem is project-guide generation in the existing installer pipeline.
Its flow is linear: discover bounded context → render guide → plan backup/replacement → preflight → publish.
A separate diagram would duplicate this small flow; it is omitted.

## D-3: A deterministic, concise project guide

Proposed, reversible. Add a canonical template under `treadle/packages/cli/harness/templates/` and an installer renderer.
Alternative: have an LLM infer architecture/conventions at every init. That requires new credentials, execution, and unverifiable policy synthesis.
The renderer reads regular files and bounded directory entries. It never runs detected scripts or queries services.
Discover package manifests at the root and immediate workspace directories; avoid dependencies, VCS metadata, and secret/state files.
Use declared package managers and actual script names, with working directories shown.
Malformed/unknown manifests produce a limited fallback, not a guessed command or stack.
Use observed top-level directory names; assign purposes only to recognized harness paths or link existing repository documentation.
Keep content concise, normally below 150 lines. Unknown conventions remain in linked project docs and the preserved backup.
Use brand configuration for the executable name; do not embed this workspace's absolute paths or product-specific module map in generic output.
Wiki examples include search, read, bounded linked context, and status. Explain missing bundle/CLI behavior and freshness limits.
Route to installed SDLC skills; refer to search-kb conditionally so initialization works independently of that skill.
The example guide is illustrative, manually source-checked for this workspace, not proof the future renderer exists.

## D-4: Safe replacement and shared document lifecycle

Proposed, reversible. Default full project init creates the guide, with `--no-project-guide` available for opt-out.
Global init, hooks-only refresh, and --remove do not generate or replace project instructions.
Guide/backup actions appear in both human and JSON dry-run output. Dry-run and JSON mode remain read-only.

Cases:

- No AGENTS.md: publish the rendered guide; do not create a synthetic backup.
- Guide bytes unchanged: no replacement and no backup mutation, across all host installs.
- Existing AGENTS.md differs and backup absent: preserve exact bytes at AGENTS.backup.md, then publish the new guide.
- Backup exists and matches the existing AGENTS.md: reuse it for a safe retry; do not overwrite it.
- Backup exists and differs: refuse guide replacement, even with --force; explain the two preserved paths.
- Target or backup is a directory/symlink, including dangling links: refuse before any planned file write.
- Inputs change after planning: refuse the stale operation; do not save a mismatched backup or silently render new content.

Snapshot guide context and file digests at plan time; check them before apply starts file copies.
Protect first backup publication with exclusive creation and persist its complete bytes before replacing the live guide.
Use a temporary file plus atomic replacement for AGENTS.md; retain failure evidence and cleanup temporary files.
This does not promise a transaction over every existing installer output. A later filesystem failure may leave other installed files;
report partial results accurately, while preserving a complete original instruction file or its backup.

Record generated-guide ownership/digest separately from removable skill/hook paths.
Removal preserves AGENTS.md and AGENTS.backup.md, including user edits. Neither is an ordinary copied component for deletion.
Cross-surface init reuses the same root guide and existing backup without per-host backup rotation.
The new guide explicitly references the prior project's backup instructions; it does not invent weaker owner gates.
Rollback uses retained original bytes only through an explicit user action, never automatic deletion/restoration during --remove.

DES-4 covers FR-6/7/8: guide renderer, plan/apply backup, scope flags, lifecycle guards, and tests.
