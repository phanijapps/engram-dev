# Candidate specification supplement

FR-1 through FR-5 retain the requirements in `spec.md`.
The following requirements add project instructions to init.

| ID | Required behavior | Acceptance |
| --- | --- | --- |
| FR-6 | Full project init creates a concise AGENTS.md with observed repository paths, supported commands, wiki retrieval, SDLC usage, and existing project-rule references. | Fixtures validate actual paths, exact detected scripts, generic fallbacks, and no fabricated stack/style/approval. A workspace example is supplied for review. |
| FR-7 | Before replacing an existing AGENTS.md, preserve its original bytes as AGENTS.backup.md. | Binary-byte comparison covers CRLF, Unicode, and arbitrary existing content; replacement failure retains the original or a complete backup. No prior backup is overwritten. |
| FR-8 | Plan and apply expose the guide/backup action honestly, remain idempotent, refuse unsafe paths or source drift, and preserve root documents during removal. | Dry-run/json writes nothing; backup collision, symlink, directory, race, repeated/multi-host init, global, hooks-only, opt-out, and remove fixtures pass. |

An existing backup with the same bytes can support retry without replacement.
A differing existing backup blocks replacement, including under --force.
An unchanged guide does not require another backup.
A generated guide never silently overrides the original project rules; it directs agents to the preserved instructions.
Guide production must not run repository scripts or connect to external services.
